# 需求底稿

## 原话

> 我要给你做个开机动画，以此为前提，配置环境，下载必要插件，为工作区进行优化和前置装备，开始

拆开是四件事：① 前提是"给 AI 做开机动画"；② 配置环境；③ 下载必要插件；④ 优化工作区、做前置装备。

## 已经落地的判断

| 判断 | 依据 |
| --- | --- |
| "开机动画"= DSH 桌面版启动时的整帧序列 | 这是"AI 所在的地方"，其余解释（启动视频/别的软件）都要先改运行环境 |
| 挂 `shell.overlay`，不占任何业务槽位 | 该槽是整帧浮层、additive、`replaceRisk: none`，用新 id 不挤掉任何既有条目 |
| 交付形态 = DSH bundle（客户端半） | 宿主只认 bundle；客户端半是纯 JS + `require('react')`，不需要构建链 |
| 不需要"下载"第三方插件 | 宿主已经带齐：React 走模块表，动画用 CSS/DOM 就够。需要下载的东西是 0 |
| 序列播完自己卸载 | 播放器用 React 状态驱动，结束后返回 `null`，DOM 不留残渣 |

## 待定的美术问题（等你拍板，不擅自定）

1. **时长**：占位版 1.8 秒（淡入 0.26 + 停留 1.1 + 淡出 0.42）。开机序列多长才不烦？
2. **风格**：现在是最克制的"一缕线 + 一个词"。要不要走 CRT 通电、点阵字滚动、Logo 绘制、粒子汇聚、终端逐行打印其中一路？
3. **文案**：现在只有 `正在启动 / INITIALIZING`。要不要出现具体字样（名字、版本、日期、一句话）？
4. **是否每次启动都播**：每开必播最像"开机"，但一天开十次会腻。要不要"每个浏览器会话只播一次"或"按住 Shift 跳过"？
5. **声音**：要不要。默认无。
6. **触发时机**：客户端模块装载后挂载，所以可能先闪一下宿主界面再盖上。若要做到"第一帧就是黑的"，得换机制（更高优先级的前置层），成本明显更高——先按现方案起步。
